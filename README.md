# CS101-Project

Холодний старт (cold start) — ситуація, коли рекомендаційній системі бракує історії взаємодій, щоб надійно рекомендувати. Розрізняють три типи:
• User cold start — новий користувач без кліків і покупок.
• Item cold start — новий товар, фільм чи заклад без взаємодій. Саме на ньому зосереджена наша презентація.
• System cold start — нова платформа, де немає ні користувачів, ні історії. 

Існує й інший варіант: об’єкт має лише кілька взаємодій, і сигнал надто слабкий.
Чому класичні методи не справляються. Collaborative Filtering і матрична факторизація вчать окремий вектор (embedding) для кожного ID користувача й товару. Прогноз має вигляд скалярного добутку цих векторів. Для нового товару вектор ніколи не навчався, бо немає прикладів, від яких можна було б учитися. Звідси випадкові рекомендації або запасний варіант «показати популярне».
Що пропонує графовий підхід. Дані подаються як граф: користувачі, товари, категорії, бренди, теги, міста — вузли, а взаємодії й належності — ребра. GNN обчислює представлення вузла як функцію його власних ознак і ознак сусідів (message passing). Новий товар ще не має покупців, але вже пов’язаний із брендом, категорією й тегами, тож може отримати осмислений вектор і потрапити до персоналізованого списку.

Учасник 2, Сергій Муха:

Гетерогенний граф. Схеми "людина купила товар" новому товару мало: покупок немає, тож немає і сусідів, з яких можна зібрати опис. Бренд, категорію і мітки виносять в окремі вузли. Тоді новий телефон і старі з'єднані через спільну точку, наприклад Samsung, хоча напряму між телефонами лінії немає.

Як опис доходить до нового товару. Повідомлення іде в той вузол, у який входить ребро. Малюють лінію "телефон -> бренд" і навпаки, інакше бренд бачить свої телефони, а новий телефон бренд не бачить. На кроці вузол змішує свій опис із середнім описом сусідів. За один крок новина проходить одну лінію: інші товари того ж бренду з'являються на другому кроці, їхні покупці на третьому. Навчання підбирає, скільки брати від картки і скільки від сусідів (які коефіцієнти ваги підставляти при оцінюванні середнього опису). Новий товар чіпляють до вже наявних вузлів і рахують опис тими самими кроками.


Учасник 3 Ігор Квеленков:

Порівняння GraphSAGE, GAT, LightGCN та їхня поведінка на Cold Start.

У графі рекомендацій безпосередні ребра «користувач — товар» показують тільки вже наявні покупки. Якщо товар чи користувач новий, цих ребер немає — виникає проблема Cold Start. Кожна модель вирішує або не вирішує її по-різному:

GraphSAGE: Замість того, щоб вчити окремий вектор для кожного вузла, модель вчиться агрегувати опис із його атрибутів (текст, категорія, ціна) та опису сусідів. Коли з'являється новий товар без покупок, GraphSAGE підтягує його власні фічі й передає інформацію через інші мета-зв'язки (наприклад, Бренд або Категорію). Вона чудово працює на Cold Start завдяки індуктивному підходу.

GAT: Модель рахує вагові коефіцієнти (увагу) між сусідніми вузлами, визначаючи, чий опис важливіший. Для нового об'єкта вона теж може використати початкові атрибути. Проте, оскільки прямих історій покупок немає, механізм уваги змушений спиратися лише на опосередковані зв'язки (спільні категорії чи бренди), через що ефективність механізму Self-Attention знижується.

LightGCN: Модель створена для максимальної швидкості й прибрала складні перетворення та фічі вузлів. Вона формує опис виключно через просте усереднення векторів сусідів у графі покупок. Якщо у нового товару немає ребер «покупка», його опис залишається випадковим — модель повністю ламається на Cold Start, оскільки їй немає звідки передати повідомлення (Message Passing).
